Build Your Personal Blog
for Free with GitHub Pages

By Belal Fergani April 2026 ~10 min read

You want your own blog. No monthly fees. No WordPress drama. No "free tier" that disappears after 14 days. Just a clean, fast, developer blog that you own. Here's exactly how I set up mine — from zero to deployed — using GitHub Pages and the Chirpy Jekyll theme.

STEP 01
Fork the Chirpy Starter Template

Head over to the chirpy-starter repo on GitHub. This is your base — a ready-made Jekyll setup that handles dark mode, categories, tags, SEO, and RSS out of the box. Click Use this template.
Then Create a new repository.

// Hit "Use this template" — top right green button
★ IMPORTANT When naming your new repository, you must use the format: yourusername.github.io — exactly your GitHub username followed by .github.io. This is what tells GitHub to host it as a Pages site for free.

STEP 02
Update _config.yml with Your Info

Inside your new repo, open _config.yml. This file is the brain of your blog — your name, URL, tagline, and social links all live here. Edit it directly in GitHub, no cloning needed for this step.

_config.yml — editing in GitHub

STEP 05
Install Ruby & Jekyll

Jekyll runs on Ruby, so you need it installed first. Go to rubyinstaller.org/downloads and grab the right version.

⚠ DO NOT SKIP THIS Install Ruby+Devkit 3.3.x (x64) — NOT Ruby 4.x. The Chirpy theme is only compatible with Ruby 3. If you install Ruby 4, things will break and editing Gemfile won't fix it. Learned this the hard way.
rubyinstaller.org/downloads
After install — Ruby34-x64 folder exists

Now install Bundler and your project dependencies:

Git Bash — Ruby install dirSHELL
# Install bundler globally (run this from the Ruby folder)
$ gem install bundler

# Go to your blog folder and install dependencies
$ cd /path/to/0xf3rgx.github.io
$ bundle install

# Verify both are working
$ ruby -v
$ bundle -v
⏱ HEADS UP bundle install can take 20–30 minutes on a first run. That's completely normal. Grab a coffee and let it do its thing.

STEP 07
Fix the TMP File Bug

If you notice the browser keeps refreshing on its own while the server is running, that's a known Jekyll/Windows issue caused by a temp file. Easy fix — create a plugin file that tells Jekyll to ignore it.

Inside _plugins/, create a new file called watcher-patch.rb and paste this:

_plugins/watcher-patch.rbRUBY
# frozen_string_literal: true

require 'jekyll-watch'

module Jekyll
  module Watcher
    extend self

    alias_method :original_listen_ignore_paths, :listen_ignore_paths

    def listen_ignore_paths(options)
      original_listen_ignore_paths(options) + [%r!.*\.TMP!i]
    end
  end
end

STEP 08
Write Your First Post

Posts in Jekyll live inside the _posts/ folder. File naming is strict — it has to follow this format exactly:

Filename FormatREQUIRED
YYYY-MM-DD-your-post-title.md

# Example:
2026-04-02-how-to-build-your-blog.md

At the top of every post file, you need front matter — the metadata block:

Post Front MatterMARKDOWN
---
title: "Build Your Blog for Free with GitHub Pages"
date: 2026-04-02 00:00:00 +0200
categories: [Tutorial]
tags: [github, Cybersecurity, blogging, Pentesting]

STEP 09
Push Your Changes & Deploy

Once you're happy with your changes locally, it's time to push them up. Three commands and you're done:

VS Code TerminalSHELL
# Stage all changes
$ git add .

# Commit with a message
$ git commit -m "customizing my personal blog"

# Push to GitHub → triggers auto-deploy
$ git push origin main

Head back to the Actions tab and watch the pipeline run. Same as before — build then deploy, both green in under a minute.
